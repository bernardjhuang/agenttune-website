1. TypeScript & Next.js AGENTS.md.

# AGENTS.md — TypeScript & Next.js Repository ## Build & Verification - Package manager: npm / pnpm (check lockfile before running). - Verify after final edits: `npm run typecheck && npm test`. ## Conventions - Prefer strict TypeScript types; avoid `any` assertions and silent catches. - Keep Server Components default; mark Client Components only at leaf interactive boundaries. - Reuse existing hooks, validation schemas, and design tokens before adding packages. ## Reporting - Summarize exact changed file paths, root cause, and observed test results only. Never claim checks passed without running them.

5. Minimal Personal Global (~/.codex/AGENTS.md)

# Global Communication Preferences - Start responses with root cause, modified files, and test output; skip long preamble. - Read existing repository files completely before editing. - Ask before running destructive git commands, dropping tables, or adding dependencies. - Never fabricate test results or unverified tool output.

6. Go Microservice

# AGENTS.md — Go Service - Verify after edits: `go test -race ./... && go vet ./...`. - Wrap errors with context (`fmt.Errorf("...: %w", err)`); avoid `panic` outside startup. - Keep interfaces narrow at consumer sites; avoid global mutable state.

7. Rust Crate

# AGENTS.md — Rust Crate - Verify after edits: `cargo clippy --all-targets -- -D warnings && cargo test`. - Avoid `.unwrap()` / `.expect()` in library code; propagate typed errors cleanly. - Keep `unsafe` blocks documented with explicit safety invariants.

8. Database & Migrations Guardrail

# AGENTS.md — Database Migrations - Never edit previously applied migration files; always generate a new forward migration. - Check locking risk on large tables (`CREATE INDEX CONCURRENTLY`, nullable column backfills). - Test both apply and rollback against local seed database before finishing.

9. Static Site & Web Accessibility

# AGENTS.md — Web Frontend - Use native semantic HTML (<button type="button">, <details>, proper <label for>) over div click handlers. - Enforce 44x44px touch targets and visible keyboard `:focus-visible` outlines. - Run build & link/HTML structure tests after every change.

10. Documentation & MDX Sync

# AGENTS.md — Documentation Repo - Check real source code / CLI `--help` output before documenting any flag or path. - Keep prose scannable and concrete; lead with exact runnable examples. - Never leave stale URLs or deprecated flags unflagged.

11. High-Speed Bug Triage Agent

# AGENTS.md — Bug Fix Mode - Write a failing reproduction test first, confirm the failure, then apply the minimal fix. - Report: (1) Root Cause in 1 sentence, (2) Minimal Diff, (3) Verified Test Output.

12. Test-Hardening Specialist

# AGENTS.md — Testing Focus - Do not mock core pure logic under test; mock only slow network/external I/O boundaries. - Never loosen failing assertions to make tests pass—fix the underlying bug or escalate cleanly.

Questions people ask.

What is the 32 KiB limit on AGENTS.md in Codex?

OpenAI Codex defaults project_doc_max_bytes to 32 KiB combined across global (~/.codex/AGENTS.md) and nested repository AGENTS.md / AGENTS.override.md files. Anything past 32 KiB gets silently truncated.

Can I share one AGENTS.md across Cursor, Windsurf, and Copilot?

Yes—many coding tools now read root AGENTS.md natively, or you can convert snippets cleanly between AGENTS.md, CLAUDE.md, and .cursor/rules/*.mdc with our Coding Rules Builder.
