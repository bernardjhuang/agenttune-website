How to keep one single source of truth across tools without drift.

Two simple repository patterns prevent conflicting build or tone rules across tools:

  1. Put shared architectural facts in AGENTS.md: Build commands, test runners, protected directories, and commit rules stay canonical in AGENTS.md. Keep CLAUDE.md ultra-short with an explicit pointer (for example @AGENTS.md plus Claude-only slash-workflow notes).
  2. Keep personal tone in user-global files, not committed repo files: Don’t force teammates into your personal banter or verbosity rules via Git. Put personal working style in ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md, or CLAUDE.local.md.

Starter communication block ideal for personal global coding-agent files (~360 characters):

## Personal Engineering Communication Style - Give root cause, exact file paths, and minimal diff or command first. - Keep prose under 4 sentences unless I ask for architectural walkthroughs. - Never extrapolate test outputs or claim checks passed unless executed after the final edit. - Ask before refactoring unrelated files or changing public APIs.

Why oversized rules files silently drop instructions.

In OpenAI Codex CLI, combining root and nested AGENTS.md files stops reading once the combined size hits project_doc_max_bytes (32 KiB default in ~/.codex/config.toml; see our GPT-6 Astra setup guide). In all coding agents, dumping entire style encyclopedias into top-level rules dilutes signal on build commands and error constraints. Keep root instructions tight (~100–250 lines), split topic-specific patterns into glob-matched files (.cursor/rules/*.mdc, .claude/rules/*.md, *.instructions.md), and safely append personal tone using our Instruction Converter & Merger.

Questions people ask.

Does Cursor read AGENTS.md or only .cursor/rules?

Cursor natively uses .cursor/rules/*.mdc (and legacy .cursorrules) for project rules alongside AGENTS.md compatibility in newer agent workflows. Keeping AGENTS.md canonical and referencing or syncing concise Cursor rules prevents drift.

Should personal personality instructions be committed into repo AGENTS.md?

Keep repo-committed AGENTS.md and CLAUDE.md focused on build commands, code style, security constraints, and tests. Place personal communication preferences in global user files (~/.claude/CLAUDE.md, ~/.codex/AGENTS.md) or gitignored CLAUDE.local.md.

What happens if AGENTS.md exceeds 32 KiB in Codex CLI?

Codex CLI stops loading additional AGENTS.md bytes past project_doc_max_bytes (default 32 KiB), which can silently cut off nested directory rules unless split cleanly or raised intentionally in ~/.codex/config.toml.
