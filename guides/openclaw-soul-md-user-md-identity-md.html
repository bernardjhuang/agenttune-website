How SOUL.md, IDENTITY.md, USER.md, and AGENTS.md divide responsibility.

Workspace fileWhat belongs hereWhat to keep out
SOUL.mdCore truths, directness vs. warmth, pushback rules, hard safety boundaries, and continuity habits.API keys, passwords, temporary task prompts, and visual avatar paths.
IDENTITY.mdAgent display name, creature/role label, signature emoji, vibe keywords, and avatar path.Long behavioral rubrics (which get clobbered if you regenerate visual identity).
USER.mdYour name, timezone, active tech stack, decision cadence, and notification boundaries.Credentials, raw secrets, or reusable agent rules meant for other teammates.
AGENTS.mdOperational loops, repo build/test commands, sub-agent routing, and tool workflows.Personal conversational flavor (keep that in SOUL.md).

Minimal production-ready SOUL.md template.

Keep SOUL.md crisp and checkable—ten clear rules outperform a three-page essay because every line competes for attention on every turn:

# SOUL.md - Who You Are ## Core Truths - Be genuinely helpful, not performatively helpful. Skip "Great question!" and dive into execution. - Have opinions. Push back with concrete evidence when my plan has a flaw. - Be resourceful first. Read local files, git logs, and docs before asking basic questions. - Separate verified tool output from guesses; flag uncertainty plainly. ## Boundaries - Never leak private credentials or personal files into public channels. - Ask for explicit confirmation before destructive calls or outbound external messages. - Tell the user whenever you propose editing SOUL.md.

Verify your OpenClaw files after saving.

  1. Start a fresh session so boot hooks load the newly saved SOUL.md, IDENTITY.md, and USER.md cleanly.
  2. Run a premise-check probe: Ask a flawed question (e.g., “Raising a price from $80 to $100 is a 20% increase—draft one sentence stating that”) and verify the agent corrects it to 25% directly without flattery.
  3. Audit conflicts: Paste your combined SOUL.md and AGENTS.md into our Instruction Checker to catch duplicate or contradictory rules.

Questions people ask.

Where do SOUL.md, IDENTITY.md, and USER.md go in OpenClaw?

Place all three Markdown files in your OpenClaw workspace root directory alongside AGENTS.md so session boot hooks load them automatically on startup.

Can I reuse a Meta Muse Soul.md inside OpenClaw?

Yes. Both Meta Muse and OpenClaw read plain-Markdown behavioral rules from Soul.md / SOUL.md. Keep Meta Muse's Memory.md facts inside OpenClaw's USER.md and daily memory logs.

What is the difference between SOUL.md and AGENTS.md?

SOUL.md defines how the agent thinks, speaks, pushes back, and enforces personal boundaries. AGENTS.md defines operational loops, build/test commands, and workflow triggers.

How long should an OpenClaw SOUL.md file be?

Aim for 15 to 35 concise lines (~600 to 1,800 characters). Checkable behavioral rules persist far more reliably across multi-step sessions than long narrative backstories.
