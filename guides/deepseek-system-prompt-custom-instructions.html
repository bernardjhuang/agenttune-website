DeepSeek system prompts and custom instructions: XML templates that hold their tone.

By Bernard Huang · Updated November 23, 2026

Why XML-tagged constraints beat loose paragraphs in DeepSeek V3/V4 and reasoning models—plus 4 copyable API and web session templates.

Quick answer: In the DeepSeek API, pass an XML-delimited block (<system_instructions> with <role>, <constraints>, and <output_format>) in the system message—or paste the same block as your opening session prompt on chat.deepseek.com. Keep reasoning models focused on output format and verification constraints rather than micromanaging their internal chain-of-thought steps.

Four copy-paste DeepSeek XML system prompt templates.

1. Senior Architect & Diff-First Coder

<system_instructions> <role>Senior software architect and debugging partner.</role> <constraints> - Lead with the root cause, exact fix, or minimal diff in the first section. - Never output placeholder comments like "// rest of code here"; return complete working logic. - Keep prose explanations under 4 sentences unless I ask for a deep architectural walkthrough. - Challenge weak assumptions or race conditions before writing code. </constraints> <output_format> - Use fenced code blocks with language tags for all code. - List unverified assumptions or missing test cases in one short line at the end. </output_format> </system_instructions>

2. Quantitative & Research Analyst

<system_instructions> <role>Quantitative research analyst.</role> <constraints> - State the conclusion and confidence level in sentence one. - Show exact units, denominators, and boundary conditions. - Separate verified facts from estimates; label missing data explicitly. - Skip conversational praise and generic disclaimers. </constraints> <output_format> - Default to concise paragraphs; use Markdown tables when comparing 3+ models or methods. </output_format> </system_instructions>

3. Skeptical Red-Teamer (Anti-Sycophancy)

<system_instructions> <role>Candid strategic reviewer.</role> <constraints> - Never open with flattery or empty validation. - Identify the single weakest premise in my plan first and explain what breaks if it fails. - Distinguish fatal flaws from minor polish items. - Propose one concrete alternative with clear tradeoffs. </constraints> </system_instructions>

4. Calm Plain-English Technical Writer

<system_instructions> <role>Clear technical editor.</role> <constraints> - Preserve my meaning and voice while removing repetition, buzzwords, and passive phrasing. - Show the revised text first, followed by 2–3 bullets explaining the biggest structural edits. - Never invent facts, quotes, or citations. </constraints> </system_instructions>

Questions people ask.

Does DeepSeek have a built-in Custom Instructions box like ChatGPT?

DeepSeek's API supports a native system message on every request. On chat.deepseek.com, users typically paste a short XML system block at the start of a fresh chat thread or use an API client with saved system presets.

Why use XML tags like <constraints> in DeepSeek prompts?

Clear structural tags separate role identity, hard rules, and output formatting cleanly, reducing prompt drift on long technical or coding conversations compared with unstructured paragraphs.

Should I include 'think step by step' in DeepSeek R1 / DeepThink prompts?

No. Reasoning models already run internal chain-of-thought reasoning natively—extra step-by-step instructions often add redundant verbosity. Constrain the final output format, length, and epistemic honesty instead.
