# Unrun protocol: a week with a Muse Soul.md

This is an unpublished protocol, not a review or a result. `docs/` is excluded from the public build. Do not publish a first-person account until real observations have been collected, checked and redacted. No account interaction or experiment is authorized by this document alone.

## Editorial purpose

A review could address whether saved communication preferences persist on repeated tasks. No search-volume ranking is established here; prioritize it using a dated Search Console export before making a demand claim.

## Setup

- Use a dedicated test account with synthetic data where possible. Do not reset a personal account as routine setup. Back up the original instruction files and document existing memory, tasks and permissions.
- Record date, client, model identifier if visible, settings and exact instruction text. Note unavailable details rather than guessing.
- Review data controls before providing any account information. Connect only a dedicated test mailbox/calendar if needed for a specifically authorized test.
- Predefine the task prompts, expected behaviors, scoring rubric and analysis. Preserve every reply, including failures.

## Seven-day observational design

Days 1–3 use the original saved configuration. Days 4–7 use one appended template block, preserving all other instructions. Repeat the same synthetic tasks in fresh conversations with the same inputs, recording any unavoidable differences. Verify the saved text directly after installation; a short greeting is not evidence of compliance.

This sequence is confounded by time, order, unequal phase lengths and memory carryover. Treat the report as a case study, not a causal estimate of a template’s effect. A controlled comparison would need matched conditions, counterbalanced order and documented memory isolation. See the published Muse persistence kit for fixed probes and a blank worksheet.

At the end, restore the exact backed-up instruction text and verify it. Remove only test artifacts created for this protocol, after checking they are no longer needed. Do not use a whole-account reset as an undo shortcut.

## Fixed task set

1. Summarize a supplied synthetic calendar and identify missing preparation details.
2. Draft, without sending, a response to a fixed synthetic email.
3. Describe the proposed reminder time and text without creating it. An actual reminder test requires a separately authorized disposable test action.
4. Prioritize three supplied tasks using fixed time and deadline constraints.
5. Summarize a supplied activity log; distinguish completed, proposed and blocked actions.
6. Correct a deliberately false premise in a fixed calculation.

For every response record: condition, day, task, full text, word count, whether it leads with an answer, missing inputs acknowledged, unsupported facts, questions asked, proposed actions, approvals requested and any actual external effects. Fewer questions or approvals is not inherently better; score whether they were appropriate to the task. Log background messages separately with their triggering configuration.

## Article outline, only after collection

1. Setup and evidence limits next to the claims they constrain.
2. Exact saved rules and predefined tasks.
3. Observations with complete denominators and representative successes and failures.
4. Differences that could also reflect order, memory or task variation.
5. What remained unchanged, without assuming an enforcement mechanism from one observation.
6. Verified restoration and remaining test artifacts.
7. A scoped conclusion for this account and period, with a downloadable redacted log.

## Publishing checks

- Screenshots exclude account identifiers and third-party private content.
- Vendor facts have current primary sources; observed behavior is labeled separately.
- Include limitations near results, not only in an end note.
